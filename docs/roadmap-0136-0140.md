# Maintenance and grouped-profile release sequence

## 0.13.6: maintenance

Correct release-status pages that still described published 0.13.5 as a
candidate, foreground the final artifact results and provide a short route to
the existing APIs. Preserve comparison, migration, grouping and detector
algorithms, historical bytes and earlier producer readers. Pair core and
benchmark at 0.13.6 and validate the new artifacts under their own identities.

## 0.14.0: grouped execution profiles

Add explicit feature-version 1.1 profiles of grouped sums between the input and
output of one captured execution. Four formulas describe modified common groups,
the largest relative difference, changes from zero and common/union coverage.
Keep exact arithmetic until finite model-value conversion. Reject undeclared
tables, incompatible declared numeric units, peer-engine or expected-output
references, invalid common-group measures and incomplete evaluation.

Use the existing training-only preprocessing, fit, separate calibration and
inference interfaces. Preserve feature-version 1.0 definitions and fingerprints.
Tests cover independent rational expectations, actual native execution over
30,000 input rows in each engine, unavailable states, persistence and existing
model integration. The runnable source example is
`examples/grouped_profiles.py`; see [the full contract](grouped-profiles.md).

## Acceptance and publication

For each version, freeze one reviewed commit/tag and run the nine technical
checks on the identified source and installed artifacts. Retain failures and
omissions. Run the compatibility probes for the admitted Python minors and
dependency profiles, review exact packages and current dependency/security
evidence, and complete independent artifact review. Then push manually, verify
TestPyPI downloads and clean consumers, and promote the identical bytes to PyPI.
No GitHub Actions or stored publishing credentials are used.

The remote Linux VM was unavailable when this work began. Development and
Windows checks proceed locally; earlier 0.13.5 Linux evidence is not relabelled
as a result for these versions. Publication remains governed by the existing
[release procedure](releasing.md) and its complete artifact-bound gates.

On an available Linux environment, select the reviewed tag, a supported Python
and isolated QA storage outside the checkout. From the repository root run:

```sh
python tools/check_candidate.py --package . --uv /path/to/uv \
  --python /path/to/python --qa-workspace /path/to/private-qa \
  --output /path/to/private-evidence/core-checks.json
python tools/check_candidate.py --package packages/equiframe-benchmark \
  --uv /path/to/uv --python /path/to/python \
  --qa-workspace /path/to/private-qa \
  --output /path/to/private-evidence/benchmark-checks.json
```

Use new output names for retries. Configure actual optional R availability and
record platform omissions honestly. Retain exact artifact hashes and downloaded
consumer results before publication. These are software acceptance conditions;
they do not establish scientific detection accuracy, a human review or delivery
of the separately maintained warehouse and portal.
